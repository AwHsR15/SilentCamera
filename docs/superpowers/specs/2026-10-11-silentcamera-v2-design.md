# SilentCamera 2.0 设计草案

状态：2026-10-11 用户已批准，并要求后续直接实施、验证并提交。

## 目标与约束

用户希望完善现有日版相机静音项目，包括功能、外观、泛用性；把常见静音方案整合为独立模式；最终提交代码、新 APK 和封装材料到 GitHub。

目标仓库：[AwHsR15/SilentCamera](https://github.com/AwHsR15/SilentCamera)，当前基线 `3d095b0`。保留 Kotlin、Jetpack Compose、Material 3 和最低 Android 8.0。不按 Samsung 品牌限制整个应用，按设备实际能力判断每个模式。

“所有日本安卓机可用”定义为：在支持的 Android 版本上可安装、检测、显示适用模式和替代拍照入口；无法保证每台设备的原厂相机声音都可关闭。所有兼容性和静音效果声明必须与证据一致。

没有用户偏好的部分采用以下默认值：中／日／英跟随系统并可切换；浅／深色跟随系统；“封装”交付为包含 APK、模块、电脑 ADB 工具、说明和校验文件的 ZIP，并附完整源码归档。

## 方案选择

1. **推荐：能力检测 + 六个独立模式 + 应用内替代拍照。** 保留原厂相机可用方案，无法修改原厂行为时提供替代拍照。可扩展，但需要模块化命令、恢复和测试。
2. 只扩展 Samsung CSC，添加 Pixel 音量组。改动较小，不能覆盖用户提出的多数品牌。
3. 只做替代相机。权限更少，但用户无法继续使用原厂相机功能。

采用方案 1。依据见 [静音方案调研](../../research/shutter-muting-approaches.md)。LSPosed / APK hook 作为有来源的外部高级方案入口，不伪装为已集成的通用执行器。

## 六个模式

### 1. Samsung CSC

- Samsung 设备推荐，Shizuku / ADB 执行。
- 保存当前 Android 用户的原值，包括“原项不存在”状态；首次应用时才备份，重复应用不得覆盖备份。
- 写入 0 后必须精确回读为 0；`null`、空输出和异常不是成功。
- 恢复原值，原本不存在则删除本应用创建的设置项。恢复后回读确认。
- 明确显示“让声音跟随系统设置”，要求原厂相机实拍验证。

### 2. 强制提示音音量组

- 运行时读取 `cmd audio help` 和设备音频策略 / dumpsys。
- 只在能唯一识别 enforced audible 目标组、支持命令且能完整备份受影响状态时允许应用。
- 不硬编码“7 对所有设备都有效”，不修改铃声、通话、媒体、闹钟音量组。
- 保存原 mute 和受影响输出设备音量，记录重启后需重新检测。
- 若设备只允许全设备统一音量而无法精确恢复不同路由原值，禁用自动修改并说明原因。

### 3. 相机应用音频控制（实验）

- 自动发现可处理拍照 intent 的应用；选择目标包，不提供任意 shell 输入。
- Shizuku / ADB 修改该包在当前 Android 用户下的 `PLAY_AUDIO`。
- 备份原状态，回读验证，精确恢复；失败时显示原因。
- 提示会影响目标应用其他音频，强制相机音和厂商逻辑可能不受限制。
- AOSP 检测到强制相机声音时可以忽略这条路径，因此不作为保证成功的推荐模式。

### 4. root 相机声音属性（高级）

- 用户主动使用该模式时请求 root；检测 root 与 resetprop。
- 仅处理检测到的已知相机声音属性，例如 `ro.camera.sound.forced`、`audio.camerasound.force`；不新增猜测属性。
- 应用前保存完整原值和设备身份；属性回读与相机实拍分开。
- 普通 ADB 权限不会被描述为能修改只读属性。
- 不自动重启；提示部分厂商服务缓存设置，重启可能恢复原值。

### 5. Magisk 音效替换（高级）

- 提供独立模块 ZIP，应用内展示安装 / 关闭 / 移除流程。
- 模块安装时扫描允许的系统音频目录与白名单快门文件名，仅覆盖存在的文件。
- 使用有效静音音频，无系统分区直接删除、无目录整体覆盖。
- 不附带未经验证的厂商相机 APK，不注入未知资源 overlay，不修改 SELinux。
- 安装与重启由 Magisk 用户流程完成；卸载模块后重启恢复。
- 如果找不到匹配文件，说明该机型可能使用 APK 内嵌或 HAL 声音，不报告已生效。

### 6. 应用内安静拍照

- CameraX 预览，拍照权限按需请求；不依赖 Shizuku 或 root。
- 高画质拍照：CameraX ImageCapture，不主动播放应用快门声音；厂商 HAL 行为需实拍验证。
- 预览帧保存：从 ImageAnalysis 保存最近的有效帧，不触发普通 still capture；明确显示分辨率和画质限制。
- 支持前后摄切换、设备支持时闪光灯 / 补光、点按对焦、缩放、参考网格、横竖屏方向、保存相册和打开成片。
- Android 10+ 用 MediaStore；Android 8–9 按系统要求请求存储权限。
- 界面显示预览和拍摄反馈，失败时保留错误信息，离开页面释放相机。
- 不承诺替代相机拥有原厂 HDR、夜景、人像和所有镜头功能。

## 界面与泛用性

主界面采用三个入口：**模式**、**拍照**、**诊断**。

- 模式：设备摘要、Shizuku / root 状态、推荐模式、独立模式卡片、应用与恢复按钮。
- 每张卡片显示“可用／需要授权／实验／不适用／待检测”，并解释具体原因。
- 配置成功显示“配置已应用，请实拍确认”，实拍后由用户记录“无声／仍有声音／未测试”。
- 不以持久化偏好代替当前设备状态；重启、用户切换、系统更新、权限撤销后重新检测。
- 拍照入口可在 Shizuku 离线时使用。
- 诊断：设备和相机版本、命令结果、操作时间、恢复备份状态、复制与系统分享。默认不包含 IMEI、序列号或 SIM 标识。
- 日志数量和单条大小设上限，操作期间禁用重复提交，仍允许退出页面。
- 响应式布局、字体缩放、可访问名称、触控尺寸、状态文字与颜色共同表达含义。

## 架构与执行

- `DeviceCapabilities`：设备、当前用户、相机应用和命令能力快照。
- `SilenceMode` / `ModeAssessment`：模式身份、要求、适用性与状态。
- `ModeController`：检测、备份、应用、回读、恢复的统一接口。
- `CommandExecutor`：使用官方 Shizuku UserService 运行受限命令；root 后端只在高级模式启用。
- `BackupRepository`：持久化原状态、设备身份和当前用户；恢复数据不参加 Android 自动备份。
- `CameraScreen`：相机生命周期与保存，独立于静音后端。
- `MainViewModel`：单一操作互斥、主线程更新 UI、结构化结果与日志。

命令参数必须来自白名单、当前诊断数据或经过验证的包名。stdout / stderr 并发读取、限长、超时和取消；失败或权限变化不能转换成成功。完成前必须回读验证。失败后如有部分变更，尝试回滚并报告真实结果；无法恢复时保留备份。

## 兼容性与验证

基础 Android 8.0+；无线 Shizuku 激活通常需 Android 11+，旧版本可用电脑 USB ADB。各模式仍以实际命令和权限能力为准。

验证包括：

- 有意义的单元测试：CSC 缺失 / 失败、能力筛选、音量组解析和歧义拒绝、当前用户范围、首次备份不覆盖、失败恢复、AppOps 与属性恢复、包名和命令输入验证。
- 构建与 Android lint；APK 签名和 ZIP 校验；模块脚本静态检查。
- 如环境支持，模拟器验证中文／日文／英文、浅／深色、权限拒绝、Shizuku 缺失和相机生命周期。
- 设备验证矩阵保留“未实机验证”。本环境没有实体手机，不能声称 Samsung、Pixel、Xperia、AQUOS、arrows、Kyocera 全部通过测试。
- 发布说明列出实际完成的检查、设备依赖和未验证项。
